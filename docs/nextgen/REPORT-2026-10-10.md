## 5. Performance (the golden baseline)

Host (PC), medians of repeated, interleaved runs vs v0.1.1: idle CPU and
context switches stay **0** for the daemon and the whole container tree,
also with four containers on a user network; daemon RSS +4 % (≈ 0.5–0.8 MB);
latency/throughput within noise. Stripped arm64 binary 7.86 → 8.72 MB.

Device (read-only `/proc` sampling, 3 × 10 s windows):
- Your production engine + 4 active containers: ≈ 50–100 ms CPU and
  70–100 context switches per second for the whole tree (not 0: your TON
  API/Explorer do real work). Daemon RSS 5.7 MB.
- Test engine with 2 mostly idle containers: ≈ 20–40 ms CPU per 10 s.

Not measured: battery, thermal, game coexistence, anything over 24 h.

## 6. Verification limits (read these before trusting the numbers)

- Device checks ran on one phone, a few minutes each; none is a long-run test.
- Network behaviour on the phone was tested with simple netcat/wget servers,
  not with your real images or nginx.
- The host and device idle numbers are not comparable with each other.
- The Web Panel uses a self-signed certificate: the owner must compare the
  fingerprint once; skipping that leaves the first pairing open to an active
  attacker on the same Wi-Fi.
- Networks are address translation, **not isolation**: any process or app on
  the phone can connect to a container's 127.77.x.y address; membership only
  decides which names resolve.

## 7. Incidents and mistakes (mine)

1. **Production engine killed.** Android 12+ limits child processes
   device-wide (~32). Running the test app's engine beside yours pushed the
   phone over; at 17:23:05 the log shows `Killing PhantomProcessRecord
   10918:libthothdock.so … Trimming phantom processes`. Your four containers
   stopped (they had no restart policy). Nothing was deleted: they showed
   `Exited (137)`. After you said yes I started them through the app's own
   Containers screen with guarded taps; all four run again. Your own
   launching of the test app also adds processes; I force-stopped it each time.
   Mitigations are documented (restart policies; never two engines at once;
   optional `adb shell device_config put activity_manager
   max_phantom_processes 2147483647`, which I did **not** apply because it
   is a system setting).
2. **A command ran on your Docker Desktop** (a backgrounded `&&` chain lost an
   `export`): a throw-away `debian:trixie` container ran and removed itself;
   the image there may have been refreshed; I removed the root-owned files it
   created.
3. **Orphaned test processes** from a harness bug (a backgrounded shell
   function); they held ports for 47 minutes; fixed, with a check that nothing
   is left behind.
4. **A claim I corrected:** I committed "17/17" for the PRoot check while the
   next run showed 15/17; the cause was the orphans above; the script now
   passes 18/18.
5. **Banner wrapped on your phone** in my first device render (64-column line
   in a 63-column terminal); tightened and re-verified.
6. **Web Panel was blind on Android** until the socket-path fix, because my
   host tests used a different folder layout.
