# UX round, 2026-10-10: Web Panel page, browser UI, Containers, banner

Status: QA build only (`com.thothterm.debian.qa.nextgen`, pin `d344fd3`). Nothing here is a
release candidate; no production app, tag, key or F-Droid metadata was touched.

## What changed

| Area | Result |
|---|---|
| Web Panel in the app | Drawer entry "Web Panel" opens a page like LAN Mode: state, who can open it (This phone only / Wi-Fi), https address, pairing code with expiry, certificate fingerprint, Start/Stop, New code, Copy, Open in browser. No polling: it redraws on a `pairing.json` file event and one timer for code expiry. |
| "Client sent an HTTP request to an HTTPS server" | The panel sniffs the first byte of each connection. TLS goes on to the normal handler. Plain HTTP gets a 307 to the same `https://` address only when the Host is an IP literal or `localhost` on the panel's own port; any other Host gets a 400 explanation page. The panel never serves content over HTTP. |
| Browser UI | New header, tiles (Running, Stopped, Images, Volumes, Stacks, Networks), container rows with Start/Stop/Restart/Logs/Shell/Delete, shell help dialog, expired-session banner, pairing steps. |
| Containers screen | Stat tiles incl. Volumes, chip row (Containers, Images, Volumes, Web Panel), new read-only Images and Volumes pages. |
| Banner | Logo-derived braille banner (compact for ~63 columns, large for desktop), owner's 95x52 art byte-for-byte under `thothfetch --logo`. |

## Verification on the phone (SM-A165F, QA package, APK sha256 prefix `edf3d9a98c58da67`)

* Unit tests: `garden-common` 375 tests and `garden-debian` 33 tests, 0 failures, 0 errors.
* Installed in place with `adb install -r`; the engine restarted both containers by policy.
* This phone only: panel starts, address `https://127.0.0.1:7690/`, browser flow
  (`tests/panel/device-e2e.py`) 11 checks, 0 failures, including both plain-HTTP cases.
* After pairing, the app shows "No active code" instead of a dead code.
* Stop Web Panel: process exits, port closed.
* Wi-Fi mode: `https://192.168.1.103:7690/` answers 200; `http://` redirects to `https://`.
* Guest regression: `docker version` (29.8.1 / 0.1.1), `docker compose version` (2.26.1-4),
  `docker run`, `docker compose up -d` / `ps` / `down`, networks listing: all OK.

## Cost of the panel (read from /proc on the device, idle, 60 s)

| Process | RSS | Threads | Context switches in 60 s | CPU ticks in 60 s |
|---|---|---|---|---|
| Panel (only while started) | 11.3 MB | 11 | +2 | +0 |
| Engine (always, unchanged) | 8.9 MB | 13 | +2 | +0 |

The panel is one extra process only while the owner has started it. The app adds no
background service for it.

## Not verified in this round

* Final banner choice among candidates A to F is not recorded; braille is the default.
* The Chrome self-signed certificate warning remains by design; the owner chose not to add CA work.
